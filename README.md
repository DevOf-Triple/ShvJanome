# Janome — интернет-магазин японских швейных машин

Курсовой проект. Магазин японской швейной техники (Janome, Juki, Brother, Toyota, Baby Lock)
на чистом PHP без фреймворков. Дизайн-концепция — **«Стежок»**: светлое полотно и багровая нить.

> Учебный проект. Компания, реквизиты, финансовые показатели и контакты выдуманы.
> Платёжный шлюз не подключён, почтовые отправления не выполняются: обращения хранятся в базе,
> менеджер связывается с покупателем сам.

---

## Возможности

| Роль              | Доступ                                                                                                                                                                      |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Гость**         | Каталог, карточка товара, о нас, инвесторам, контакты, обратная связь, вход и регистрация. Корзины и избранного нет — кнопки ведут на вход с возвратом на исходную страницу |
| **Покупатель**    | Всё выше + корзина, избранное, оформление и отмена заказа, кабинет: профиль, аватар, история заказов, смена пароля                                                          |
| **Администратор** | Всё выше + админка: статистика, CRUD товаров/категорий/брендов, статусы заказов, роли пользователей, обращения, просмотр базы только на чтение                              |

Ключевое:

- каталог с фильтрами (бренд, категория, тип машинки, цена), поиском, сортировкой и пагинацией — без перезагрузки страницы;
- избранное авторизованного **всегда первым** в каталоге при любой сортировке;
- корзина хранится в БД, а не в сессии: не теряется при закрытии вкладки;
- заказ оформляется в транзакции с резервом остатка, отмена возвращает товары на склад;
- загрузка фото товаров и аватаров файлом с проверкой типа и размера;
- адаптив до 375 px, анимации появления блоков, тосты вместо `alert`.

## Установка и запуск

### 1. Домен в OSPanel

Создай домен, указывающий на **корень проекта** (папку, где лежат `pages/`, `api/`, `config/`).
Точка входа — `pages/index.php`, поэтому открывать нужно `http://<домен>/pages/index.php`.

Чтобы домен открывался сразу на главной, положи в корень `.htaccess`:

```apache
DirectoryIndex pages/index.php
ErrorDocument 404 /pages/404.php
```

### 2. Импорт базы данных

Через phpMyAdmin: меню OSPanel → «Дополнительно» → phpMyAdmin, вход `root` без пароля,
вкладка **«Импорт»** → выбрать `janome_base.sql` → «Вперёд».

Базу создавать вручную не нужно — `CREATE DATABASE janome_base` есть внутри дампа.
Повторный импорт перезаписывает таблицы.

Либо через консоль OSPanel:

```bash
mysql -u root < janome_base.sql
```

Дамп наполняет: 5 брендов, 5 категорий, 12 товаров с реальными моделями, характеристиками
в `specs` (JSON) и ценами в рублях. Картинки товаров указывают на плейсхолдер.

### 3. Подключение к БД

Скопируй `config/db.example.php` в `config/db.php` и поправь доступы:

```php
$host = '127.0.1.28';   // адрес MySQL-модуля OSPanel
$dbname = 'janome_base';
$dbuser = 'root';
$dbpass = '';
```

**Важно про `$host`.** OSPanel выделяет каждому модулю свой loopback-адрес, поэтому
`127.0.0.1` может не работать. Свой адрес смотри в настройках OSPanel:
модуль MySQL → адрес/порт. Файл `config/db.php` в git не попадает (см. `.gitignore`).

### 4. Тестовые аккаунты

Пользователей в дампе нет намеренно: пароли создаются только через `password_hash()` в PHP,
фейковых хэшей в SQL не хранится. Запусти сид:

```
http://<домен>/seed_admin.php
```

или в консоли OSPanel:

```bash
php seed_admin.php
```

Создадутся два аккаунта:

| Логин   | Пароль     | Роль          |
| ------- | ---------- | ------------- |
| `admin` | `admin123` | администратор |
| `user`  | `user123`  | покупатель    |

Повторный запуск безопасен — существующие аккаунты пропускаются.
**После первого входа смени пароли** (кабинет → «Безопасность») и удали `seed_admin.php` с сервера.

### 5. Готово

```
http://<домен>/pages/index.php
```

## База данных

База `janome_base`, 9 таблиц, InnoDB, `utf8mb4_unicode_ci`, внешние ключи.

| Таблица       | Назначение                                                            |
| ------------- | --------------------------------------------------------------------- |
| `users`       | аккаунты: логин, хэш пароля, ФИО, email, телефон, адрес, аватар, роль |
| `brands`      | бренды каталога                                                       |
| `categories`  | категории техники                                                     |
| `products`    | товары: цена, старая цена, остаток, `specs` JSON, фото, активность    |
| `cart_items`  | корзина, `UNIQUE(user_id, product_id)`                                |
| `favorites`   | избранное, `UNIQUE(user_id, product_id)`                              |
| `orders`      | заказы: номер, сумма, статус, доставка, оплата, адрес, телефон        |
| `order_items` | позиции заказа — снимок названия и цены на момент покупки             |
| `feedback`    | обращения: имя, email, сообщение, отметка прочитанного                |

### Поведение внешних ключей

| Связь                                            | ON DELETE | Почему так                                                           |
| ------------------------------------------------ | --------- | -------------------------------------------------------------------- |
| `products` → `brands` / `categories`             | RESTRICT  | нельзя удалить бренд или категорию с товарами                        |
| `cart_items`, `favorites` → `users` / `products` | CASCADE   | удалили пользователя или товар — корзина и избранное чистятся сами   |
| `orders` → `users`                               | RESTRICT  | история покупок не удаляется вместе с аккаунтом                      |
| `order_items` → `orders`                         | CASCADE   | позиции живут вместе с заказом                                       |
| `order_items` → `products`                       | RESTRICT  | товар из заказа нельзя удалить — он скрывается через `is_active = 0` |
| `feedback` → `users`                             | SET NULL  | аккаунт удалён, обращение осталось                                   |

## Бизнес-логика

### Авторизация

- вход **по логину**, не по email;
- пароли только `password_hash()` / `password_verify()`, алгоритм обновляется через `password_needs_rehash()`;
- роль берётся из `users.role` и кладётся в сессию;
- возврат после входа через параметр `return` — принимаются только локальные пути, петли на `login.php` / `register.php` отрезаются.

### Каталог

- тип машинки выводится из `specs->>'Тип управления'`, для оверлоков и вышивальных — из категории, поэтому фильтр не дублирует категорию;
- сортировка избранного: `ORDER BY is_favorite DESC, <выбранный порядок>`;
- пагинация по 9 товаров, все запросы подготовленные.

### Корзина и заказ

- корзины гостя не существует ни в сессии, ни в БД;
- количество режется по остатку на сервере, пересчёт суммы через fetch;
- удаление можно отменить — позиция возвращается с прежним количеством;
- заказ создаётся в одной транзакции: `orders` + `order_items`, списание остатка с защитой `AND stock >= ?`, очистка корзины, генерация номера `JN-ГГГГММДД-NNNN`;
- сумма и цены берутся **только из БД**, клиентским цифрам доверия нет.

### Статусы заказа

```
new (Новый)
 ├→ processing (В обработке) ─→ shipped (Отправлен) ─→ done (Выполнен)
 └→ cancelled                    └→ cancelled

done / cancelled — финальные, переходов нет
```

Отмена доступна только до отправки, потому что она возвращает остатки на склад.
Правило проверяется на сервере, а не только составом селекта в интерфейсе.
Покупатель может отменить **свой** заказ в статусе `new`, администратор — по цепочке выше.

### Оплата

`on_delivery` — при получении, `card` — карта-заглушка. Поля карты проверяются только
в браузере (формат, срок, алгоритм Луна) и **на сервер не отправляются**: в заказ уходит
лишь отметка о способе оплаты.

## Безопасность

- все запросы к БД — подготовленные выражения PDO, эмуляция prepares отключена;
- весь вывод через `htmlspecialchars()` (`e()` в `helpers.php`);
- CSRF-токен в сессии, проверка на каждом изменяющем запросе (POST-поле или заголовок `X-CSRF-Token`);
- роль проверяется **на сервере в каждом** `api/admin/*.php` через `api_require_admin()`, а не скрытием кнопок в шапке;
- сессионная кука: `httponly`, `samesite=Lax`, `secure` при HTTPS; идентификатор сессии обновляется при входе и смене пароля;
- троттлинг: вход — 5 неудач за 15 минут, смена пароля — 5 неудач за 15 минут, обращения — 5 за 10 минут;
- обратная связь: honeypot-поле + отсечка слишком быстрой отправки, дубликат текста за 5 минут отклоняется;
- загрузка файлов: тип определяется по содержимому (`finfo` + `getimagesize`), а не по расширению; лимит 2 МБ, имя файла случайное (`random_bytes`), старый файл удаляется только внутри своей папки;
- просмотр базы (`api/admin/db_view.php`) — только GET, только белый список таблиц и колонок, произвольный SQL не выполняется, `password_hash` не выбирается вообще;
- свою роль менять нельзя, последнего администратора разжаловать нельзя;
- ответ о неверном входе не раскрывает, существует ли логин.

## Дизайн-система «Стежок»

Светлое полотно и багровая нить. Все переменные — в `assets/css/base.css`.

| Переменная   | Цвет      | Назначение                      |
| ------------ | --------- | ------------------------------- |
| `--wine-900` | `#4E0B15` | подвал, тёмные акценты          |
| `--wine-700` | `#7A1220` | основной багровый               |
| `--wine-500` | `#B01B2E` | кнопки, активные состояния      |
| `--wine-300` | `#D42A3F` | hover                           |
| `--white`    | `#FFFFFF` | основной фон                    |
| `--linen`    | `#FBF6F6` | фон секций, «небелёное полотно» |
| `--line`     | `#E8D5D8` | границы                         |
| `--ink`      | `#2A1013` | текст                           |
| `--muted`    | `#6B5558` | вторичный текст                 |

Фирменные детали:

1. **Фон-полотно** — два `repeating-linear-gradient` под 0° и 90° с шагом 4 px, прозрачность ≈ 0.03. Без зерна и blur-пятен.
2. **Строчка** вместо обычных линий — пунктир 6/6 толщиной 2 px цвета `--line`.
3. **Карточка-лоскут** — тонкая сплошная рамка снаружи, пунктирная строчка внутри с отступом 6 px, подъём на 4 px при hover.
4. **Кнопка-шов** — багровая плашка с пунктиром по внутреннему периметру, стежки смещаются через анимацию `background-position`.
5. **Сантиметровая лента** — декоративная шкала с делениями: в hero, в подвале, вдоль ползунка цены.
6. **Логотип** — inline SVG: игла с нитью и шпульный контур (мотив «змеиного глаза»), рядом wordmark шрифтом PT Serif.

Анимации: reveal блоков через `IntersectionObserver`, нить под заголовками секций «прошивается» слева направо, подчёркивание-нить у ссылок растёт при hover, счётчики набирают значение при появлении. Скругления 4–8 px, липкая шапка, label-надзаголовок на каждой странице, тосты вместо `alert`, аккордеоны на `details/summary`. Всё уважает `prefers-reduced-motion`.

## Картинки

### Товары

Файлы кладутся в `assets/img/products/`, путь хранится в `products.image_path` от корня проекта.
Рекомендации: пропорции **4:3**, размер 800×600 (или 1200×900), формат WebP или JPG, до 300 КБ.

Быстрый способ разложить фото по slug-ам товаров:

```sql
USE janome_base;
UPDATE products SET image_path = CONCAT('assets/img/products/', slug, '.jpg');
```

После этого в папке должны лежать файлы вида `janome-dc-603.jpg`, `juki-mo-654de.jpg` и т. д.
Если файла нет, карточка покажет встроенный SVG-плейсхолдер — битых картинок не будет.

Из админки фото загружается файлом: вкладка «Товары» → редактор → блок «Фото товара»
(JPG/PNG/WebP, до 2 МБ, минимум 200×150 px, имя файла случайное).

### Аватары

Загружаются пользователем в кабинете: вкладка «Профиль» → блок «Аватар».
Проверка типа по содержимому, лимит 2 МБ, минимум 64×64 px, имя `bin2hex(random_bytes(16))`,
хранение в `assets/img/avatars/`, предыдущий файл удаляется. Папка создаётся автоматически.

## Проверка работоспособности

Быстрый сценарий для защиты:

1. **Гость:** открыть каталог, отфильтровать по бренду и цене, найти модель поиском, открыть карточку. Нажать «В корзину» — уводит на вход с возвратом.
2. **Регистрация:** создать аккаунт, войти по логину (не по email).
3. **Каталог:** отметить 2–3 товара сердечком, сменить сортировку — избранное остаётся первым.
4. **Корзина:** изменить количество, удалить позицию и нажать «Вернуть» в тосте.
5. **Заказ:** оформить с курьером и с самовывозом, проверить, что остаток уменьшился. Отменить заказ — остаток вернулся.
6. **Кабинет:** сменить ФИО и телефон, загрузить аватар, сменить пароль (старый обязателен), выйти и войти с новым.
7. **Обратная связь:** отправить обращение гостем и авторизованным.
8. **Админка (под `admin`):** дашборд, создать товар с фото, снять товар с продажи, поменять статус заказа, поменять роль пользователя, отметить обращение прочитанным, открыть просмотр базы.
9. **Доступы:** зайти под `user` и открыть `pages/admin.php` — редирект на главную с тостом. Прямой запрос к `api/admin/stats.php` — 403.

## Если что-то не работает

| Симптом                                                             | Причина и решение                                                                                                                                                                                                                                                            |
| ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `{"ok":false,"error":"Ошибка подключения к базе данных"}`           | Неверные доступы в `config/db.php`. Проверь `$dbname = 'janome_base'` и `$host` — адрес MySQL-модуля OSPanel, не обязательно `127.0.0.1`                                                                                                                                     |
| «Нет config/db.php»                                                 | Не скопировал `db.example.php` в `db.php`                                                                                                                                                                                                                                    |
| Белая страница, в логах PHP fatal                                   | Ошибка в запросе или обрезанный файл. Включи `display_errors` или прогони `php -l pages/<файл>.php`                                                                                                                                                                          |
| Админка открывается, но контент пустой, а в исходнике разметка есть | **Блокировщик рекламы.** Классы с префиксом `ad-` (`.ad-panel`, `.ad-main`, `.ad-hero`) попадают под generic-фильтры EasyList и получают `display:none !important`, который не перебивается даже инлайном. В проекте используется префикс `adm-` — не переименовывай обратно |

## Ограничения учебного проекта

Сделано осознанно, чтобы не изображать продакшн:

- платёжный шлюз не подключён, оплата картой — заглушка без передачи данных;
- почтовый шлюз не подключён, поэтому нет `mailto` и писем: обращения живут в таблице `feedback`;
- стоимость доставки не тарифицируется, сумма заказа — по ценам товаров;
- карта на странице контактов — схема-плейсхолдер, внешний сервис не подключается;
- цифры на страницах «О нас» и «Инвесторам» выдуманы и помечены как выдуманные;
- показатели каталога (число моделей, брендов, остаток, заказы) считаются из БД.
